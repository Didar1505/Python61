# 1. Введение в ООП

## 1.1. Зачем нужно объектно-ориентированное программирование?

Представим интернет-магазин. В нём есть товары, покупатели, заказы и корзины. У каждого товара есть название, цена и количество на складе. С товаром можно выполнять действия: изменить цену, продать несколько единиц, пополнить запас.

Если программа небольшая, достаточно нескольких переменных и функций. Но когда объектов становится много, приходится следить за тем, какие переменные относятся к конкретному товару, передавать их между функциями и не забывать обновлять нужные значения.

Удобнее представить каждый товар как самостоятельную сущность, которая хранит собственные данные и умеет выполнять относящиеся к ней действия.

**Объектно-ориентированное программирование (ООП)** — это подход к организации программы, при котором данные и связанные с ними действия представляются в виде взаимодействующих объектов.

- **Класс** — описание того, какие данные и действия имеют объекты определённого вида.
- **Объект** — конкретный экземпляр класса со своими данными.
- **Атрибут** — данные объекта, например цена товара.
- **Метод** — функция, связанная с объектом, например изменение цены.
- **Состояние объекта** — его текущие данные, которые могут изменяться во время работы программы.

Аналогия: класс автомобиля описывает общие характеристики и действия автомобиля, а конкретные автомобили имеют собственный цвет, скорость и количество топлива. Нажатие педали газа меняет скорость конкретного автомобиля, а не всех автомобилей сразу.

## 1.2. Пример 1. Один банковский счёт: переменные и функции

Задача: хранить баланс счёта и выполнять пополнение. Пока счёт только один, достаточно обычной функции.

```python
balance = 1000


def deposit(balance, amount):
    return balance + amount


balance = deposit(balance, 500)
print("Баланс:", balance)
```

Результат:

```text
Баланс: 1500
```

Как работает программа:

1. Переменная `balance` хранит начальный баланс.
2. Функция `deposit()` получает баланс и сумму пополнения.
3. `return` возвращает новый баланс.
4. Основная программа сохраняет результат обратно в `balance`.

Этот подход вполне корректен. Он особенно удобен для простых вычислений. Однако функция сама не хранит состояние счёта: при каждом вызове нужно передавать баланс и сохранять результат.

## 1.3. Пример 2. Та же задача с использованием ООП

Теперь объединим баланс и операции со счётом в одном классе.

```python
class BankAccount:
    def __init__(self, owner, balance):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        self.balance = self.balance + amount


account = BankAccount("Анна", 1000)
account.deposit(500)

print("Владелец:", account.owner)
print("Баланс:", account.balance)
```

Результат:

```text
Владелец: Анна
Баланс: 1500
```

Как работает программа:

1. При создании объекта `account` метод `__init__()` записывает имя владельца и баланс.
2. `account.deposit(500)` вызывает метод конкретного объекта.
3. `self` внутри метода указывает на этот объект.
4. Метод изменяет `self.balance`. Отдельно передавать баланс и сохранять возвращаемый результат не требуется.

Здесь метод изменяет состояние объекта. Он не обязан возвращать новый баланс: при отсутствии `return` Python возвращает `None`, а изменённый баланс уже хранится в объекте.

**Преимущество:** данные счёта и действия с ним находятся рядом. Пока класс не проверяет корректность пополнения — это будет исправлено при изучении инкапсуляции.

## 1.4. Пример 3. Несколько независимых объектов

Преимущество классов особенно заметно, когда нужно работать с несколькими однотипными сущностями.

```python
class Player:
```

## 1.5. Когда ООП полезно?

| Обычные функции и переменные | Классы и объекты |
|---|---|
| Удобны для отдельных вычислений | Удобны для сущностей с данными и поведением |
| Данные передаются через параметры | Объект хранит собственное состояние |
| Хорошо подходят для небольших алгоритмов | Помогают организовать множество взаимодействующих сущностей |
| Код можно повторно использовать через функции | Код можно повторно использовать через методы, классы и наследование |

ООП не заменяет функции и не делает любую программу автоматически лучше. В больших программах оно помогает разделять ответственность, поддерживать согласованность данных и изменять отдельные части системы. Для простого вычисления площади отдельный класс, скорее всего, не нужен.

Далее рассмотрим четыре распространённых принципа ООП по отдельности.

# 2. Инкапсуляция

## 2.1. Зачем она нужна?

Представьте банкомат. Чтобы снять деньги, пользователь выбирает сумму. Банкомат проверяет, достаточно ли средств. Пользователь не может просто написать на экране произвольный новый баланс.

Аналогично объекту полезно предоставлять понятные способы изменения своих данных, чтобы он мог проверять допустимость изменений.

**Инкапсуляция** — объединение данных и методов работы с ними внутри объекта, а также организация контролируемого доступа к его внутреннему состоянию.

Она помогает соблюдать правила: баланс не должен случайно стать отрицательным, количество товара не должно уменьшаться ниже нуля, здоровье персонажа должно оставаться в допустимых пределах.

## 2.2. Пример 4. Проблема прямого изменения атрибута

```python
class Product:
    def __init__(self, name, quantity):
        self.name = name
        self.quantity = quantity


product = Product("Книга", 10)
product.quantity = -5

print(product.name, product.quantity)
```

Результат:

```text
Книга -5
```

Python разрешает присваивать значение открытому атрибуту. Но отрицательный остаток товара не соответствует правилам нашего магазина. Ошибки выполнения нет, хотя состояние объекта неверное с точки зрения задачи.

Открытые атрибуты сами по себе не являются плохой практикой: например, название можно оставить открытым, если специальная проверка не нужна. Контроль требуется прежде всего там, где есть ограничения.

## 2.3. Пример 5. Контролируемое пополнение банковского счёта

В Python один знак подчёркивания в начале имени, например `_balance`, означает, что атрибут предназначен для внутреннего использования. Это соглашение, а не запрет доступа.

```python
class BankAccount:
    def __init__(self):
        self._balance = 0

    def deposit(self, amount):
        if amount <= 0:
            return False

        self._balance = self._balance + amount
        return True

    def get_balance(self):
        return self._balance


account = BankAccount()
print(account.deposit(1000))
print(account.deposit(-500))
print("Баланс:", account.get_balance())
```

Результат:

```text
True
False
Баланс: 1000
```

Порядок работы:

1. Новый счёт имеет баланс 0.
2. Метод `deposit()` проверяет сумму перед изменением состояния.
3. Если сумма неположительная, `return False` досрочно завершает метод.
4. При корректной сумме баланс увеличивается, метод возвращает `True`.
5. `get_balance()` позволяет узнать текущий баланс.

**Преимущество:** объект самостоятельно отвечает за проверку своих данных. Код, вызывающий метод, может узнать, успешно ли выполнена операция.

Технически `account._balance = -100` всё ещё возможно. Подчёркивание просит разработчика не обращаться к этому атрибуту напрямую.

## 2.4. Пример 6. Два подчёркивания в имени атрибута

Два подчёркивания в начале имени (`__quantity`) заставляют Python изменить его внутреннее имя. Это называется **преобразованием имени (name mangling)**. Такой механизм помогает избежать случайного обращения к внутреннему атрибуту под исходным именем, особенно в дочерних классах.

```python
class Product:
    def __init__(self, name):
        self.name = name
        self.__quantity = 0

    def restock(self, amount):
        if amount <= 0:
            return False
        self.__quantity = self.__quantity + amount
        return True

    def sell(self, amount):
        if amount <= 0 or amount > self.__quantity:
            return False
        self.__quantity = self.__quantity - amount
        return True

    def get_quantity(self):
        return self.__quantity


product = Product("Наушники")
product.restock(10)
print(product.sell(3))
print(product.sell(20))
print("На складе:", product.get_quantity())
```

Результат:

```text
True
False
На складе: 7
```

Методы `restock()` и `sell()` проверяют количество и только потом меняют внутренний остаток. Метод `get_quantity()` возвращает текущее значение.

Если попробовать прочитать `product.__quantity`, возникнет `AttributeError`: Python не найдёт атрибут под таким именем. Внутреннее имя в данном классе — `_Product__quantity`. Технически к нему можно обратиться, но делать этого не следует. Это не механизм безопасности и не настоящая недоступность данных.

## 2.5. Пример 7. Здоровье игрового персонажа

Здоровье персонажа не должно быть меньше 0 и больше 100. Вместо того чтобы проверять это во всех частях игры, поместим правила в класс.

```python
class Player:
    def __init__(self, name):
        self.name = name
        self.__health = 100

    def take_damage(self, damage):
        if damage <= 0:
            return
        self.__health = max(0, self.__health - damage)

    def heal(self, amount):
        if amount <= 0:
            return
        self.__health = min(100, self.__health + amount)

    def get_health(self):
        return self.__health


player = Player("Алекс")
player.take_damage(40)
print(player.get_health())
player.heal(70)
print(player.get_health())
player.take_damage(150)
print(player.get_health())
```

Результат:

```text
60
100
0
```

`max()` выбирает большее значение, поэтому здоровье не опускается ниже 0. `min()` выбирает меньшее значение, поэтому лечение не поднимает здоровье выше 100. Методы игнорируют неположительные суммы урона и лечения.

**Преимущество:** независимо от того, какая часть игры вызывает методы, правила здоровья остаются в одном месте. Здесь лечение при нулевом здоровье разрешено по условию примера; в итоговом проекте правила будут другими.

## 2.6. Открытые и внутренние атрибуты

| Имя | Смысл | Особенности |
|---|---|---|
| `self.name` | Открытый атрибут | Обычный доступ извне |
| `self._balance` | Внутренний по соглашению | Python не запрещает обращаться напрямую |
| `self.__health` | Имя с преобразованием | Снижает риск случайного обращения и конфликтов имён |
| `__init__` | Специальный метод Python | Два подчёркивания с обеих сторон имеют другое назначение |

Типичные ошибки: считать `_` запретом доступа; считать `__` защитой от любого внешнего изменения; делать все атрибуты закрытыми без причины; создавать методы изменения без проверок.

**Главная мысль:** инкапсуляция нужна не ради подчёркиваний, а ради понятных правил работы с состоянием объекта.

# 3. Наследование

## 3.1. Зачем оно нужно?

В игре есть воин, маг и лучник. Все они имеют имя, здоровье и могут получать урон. При этом у каждого свой способ атаки.

Если написать три независимых класса, придётся несколько раз повторить одинаковые атрибуты и методы. Когда правила здоровья изменятся, потребуется исправить каждый класс отдельно.

Можно создать один общий класс персонажа и на его основе описать конкретные виды персонажей.

**Наследование** — создание нового класса на основе существующего класса с возможностью использовать, дополнять или изменять его поведение.

- **Родительский (базовый) класс** — класс, от которого наследуются.
- **Дочерний класс** — класс, который получает поведение родителя и может его расширять.

## 3.2. Пример 8. Простое наследование

У всех животных есть имя, и каждое животное может есть. Собака дополнительно умеет лаять.

```python
class Animal:
    def __init__(self, name):
        self.name = name

    def eat(self):
        print(self.name, "ест")


class Dog(Animal):
    def bark(self):
        print(self.name, "говорит: Гав!")


dog = Dog("Рекс")
dog.eat()
dog.bark()
```

Результат:

```text
Рекс ест
Рекс говорит: Гав!
```

Разберём код:

1. `Animal` содержит общие данные и метод `eat()`.
2. Запись `class Dog(Animal):` означает, что класс `Dog` наследуется от `Animal`.
3. В классе `Dog` нет собственного `__init__()`, поэтому используется метод родителя.
4. Объект `dog` может вызвать унаследованный `eat()` и собственный `bark()`.

**Преимущество:** общие атрибуты и методы не нужно повторять в каждом дочернем классе.

## 3.3. Пример 9. Дополнение родительского класса

В системе пользователей обычный пользователь может входить в приложение, а администратор дополнительно может управлять пользователями.

```python
class User:
    def __init__(self, name):
        self.name = name

    def login(self):
        print(self.name, "вошёл в систему")


class Admin(User):
    def show_panel(self):
        print(self.name, "открыл панель администратора")


user = User("Иван")
admin = Admin("Олег")

user.login()
admin.login()
admin.show_panel()
```

Результат:

```text
Иван вошёл в систему
Олег вошёл в систему
Олег открыл панель администратора
```

## 3.4. Пример 10. Переопределение методов

Иногда дочернему классу подходит не всё поведение родителя. Например, у обычного транспорта и самолёта движение описывается по-разному.

**Переопределение метода** — создание в дочернем классе метода с тем же именем, что и у родителя, но с другой реализацией.

```python
class Transport:
    def move(self):
        print("Транспорт движется")


class Airplane(Transport):
    def move(self):
        print("Самолёт летит")


transport = Transport()
plane = Airplane()

transport.move()
plane.move()
```

Результат:

```text
Транспорт движется
Самолёт летит
```

Когда вызывается `plane.move()`, Python сначала ищет метод в классе `Airplane`. Он существует, поэтому выполняется именно его код. Метод родителя при этом не изменяется: другие объекты `Transport` продолжают работать как раньше.

**Преимущество:** дочерний класс может иметь собственное поведение, сохраняя общую структуру родителя.

## 3.5. Пример 11. Использование super() в __init__()

Представим систему сотрудников. У каждого есть имя и зарплата. У менеджера дополнительно есть название отдела. Повторять присваивания имени и зарплаты в классе менеджера не нужно.

В простом случае одиночного наследования `super()` позволяет обратиться к реализации метода родительского класса.

```python
class Employee:
    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

    def show_info(self):
        print(self.name, "— зарплата:", self.salary)


class Manager(Employee):
    def __init__(self, name, salary, department):
        super().__init__(name, salary)
        self.department = department


manager = Manager("Анна", 60000, "Продажи")
manager.show_info()
print("Отдел:", manager.department)
```

Результат:

```text
Анна — зарплата: 60000
Отдел: Продажи
```

Порядок работы:

1. При создании менеджера запускается его `__init__()`.
2. `super().__init__(name, salary)` вызывает родительский метод для того же объекта.
3. Родитель создаёт атрибуты `name` и `salary`.
4. Дочерний метод создаёт дополнительный атрибут `department`.
5. Унаследованный `show_info()` использует уже созданные атрибуты.

Обратите внимание: `super()` не создаёт ещё один объект сотрудника. Он позволяет использовать реализацию родителя для текущего объекта.

## 3.6. Пример 12. Использование super() в обычных методах

`super()` полезен не только при создании объекта. Иногда нужно сохранить работу родительского метода и дополнить её.



## 3.7. Когда использовать наследование?

Наследование уместно, если дочерний объект действительно является разновидностью родительского: собака — животное, менеджер — сотрудник, книга — товар.

Если один объект содержит другой, наследование обычно не подходит. Например, автомобиль имеет двигатель, но автомобиль не является двигателем. В такой ситуации можно хранить объект двигателя в атрибуте автомобиля. Этот подход называют **композицией**; подробнее он будет показан в итоговом проекте на примере арены, содержащей персонажей.

Типичные ошибки: забыть скобки с родительским классом; забыть вызвать родительский `__init__()` при его переопределении; ошибиться в имени метода; применять наследование только для экономии нескольких строк, когда между классами нет логической связи.

**Главная мысль:** наследование позволяет выделить общее поведение и описывать различия в дочерних классах.

# 4. Полиморфизм

## 4.1. Зачем он нужен?

Представим приложение, которое управляет разными устройствами. Телевизор, лампа и кондиционер включаются по-разному, но пользователю удобно обращаться к каждому с одной и той же командой — «включить».

Программе также удобно работать с разными объектами одинаковым способом. Вместо отдельной инструкции для каждого вида объекта можно использовать общий метод.

**Полиморфизм** — возможность обращаться к разным объектам через одинаковый способ взаимодействия, получая поведение, соответствующее конкретному объекту.

В рассматриваемых примерах таким способом является вызов метода с одним именем и согласованным набором аргументов.

## 4.2. Пример 13. Одинаковый метод у разных классов

```python
class Dog:
    def speak(self):
        return "Гав!"


class Cat:
    def speak(self):
        return "Мяу!"


dog = Dog()
cat = Cat()

print(dog.speak())
print(cat.speak())
```

Результат:

```text
Гав!
Мяу!
```

У обоих классов есть метод `speak()`, но каждый реализует его по-своему. Оба метода возвращают строку. Это позволяет использовать общий вызов и получать подходящий результат.

В Python для такого полиморфизма не обязательно иметь общий родительский класс. Достаточно, чтобы объекты поддерживали нужное поведение.

## 4.3. Пример 14. Работа с разными объектами в цикле

Представим, что нужно воспроизвести звуки нескольких животных.

```python

    def speak(self):
        return "Му!"

for animal in animals:
```

## 4.6. Полиморфизм и проверки типов

Если у всех нужных объектов есть согласованный метод, нет необходимости писать отдельные ветви для собаки, кошки, коровы и каждого нового животного. Вызывайте общий метод и позволяйте объекту выбирать собственное поведение.

Подход, при котором важнее наличие нужного поведения, чем принадлежность к конкретному классу, в Python часто называют **утиной типизацией**. Название связано с аналогией: если объект ведёт себя как утка, в данной задаче его можно использовать как утку.

Типичные ошибки: разные имена методов; несовместимые аргументы; возвращение строки одним классом и числа другим, когда вызывающий код ожидает число; предположение, что одного совпадения имени всегда достаточно. Методы должны также выполнять согласованную по смыслу задачу.

**Главная мысль:** полиморфизм позволяет одному участку программы работать с разными объектами без знания деталей их классов.

# 5. Абстракция

## 5.1. Зачем она нужна?

Чтобы отправить сообщение в мессенджере, достаточно выбрать получателя, набрать текст и нажать кнопку отправки. Необязательно знать, каким образом текст передаётся по сети, как сервер обрабатывает запрос или как устроено хранилище сообщений.

Программист может аналогичным образом создать объект, предоставляющий несколько понятных действий, и скрыть за ними подробности выполнения. Кроме того, при создании класса не нужно описывать абсолютно все свойства реального объекта — достаточно тех, которые важны для конкретной задачи.

**Абстракция** — выделение существенных характеристик и действий объекта для конкретной задачи и представление их через понятный интерфейс без необходимости знать все детали реализации.

**Интерфейс объекта** в наших примерах — набор методов и открытых атрибутов, которыми может пользоваться остальная программа. Это не обязательно графический интерфейс и не специальная конструкция Python.

Для изучения абстракции достаточно обычных классов. Абстрактные базовые классы и модуль `abc` понадобятся на более продвинутом этапе.

## 5.2. Пример 17. Выделение необходимых характеристик

Для сервиса аренды автомобилей важно знать модель, цену аренды и уметь вычислить стоимость. Не нужно описывать устройство двигателя, материал сидений и каждую деталь автомобиля.

```python
class RentalCar:
    def __init__(self, model, daily_price):
        self.model = model
        self.daily_price = daily_price

    def calculate_cost(self, days):
        return self.daily_price * days


car = RentalCar("Toyota Corolla", 2500)
print(car.model)
print("Стоимость аренды:", car.calculate_cost(3))
```

Результат:

```text
Toyota Corolla
Стоимость аренды: 7500
```

Класс представляет только данные и действия, существенные для расчёта аренды. Метод принимает количество дней и возвращает стоимость. В другой программе, например в автосервисе, тот же автомобиль потребовал бы других характеристик.

**Преимущество:** модель остаётся небольшой и соответствует задаче. Абстракция не означает обязательное использование внутренних атрибутов.

## 5.3. Пример 18. Кофемашина с простым интерфейсом

Пользователю удобно вызвать один метод приготовления кофе, не управляя каждой отдельной операцией.

```python
class CoffeeMachine:
    def _heat_water(self):
        print("Нагрев воды")

    def _grind_beans(self):
        print("Измельчение зёрен")

    def _brew(self):
        print("Приготовление кофе")

    def make_coffee(self):
        self._heat_water()
        self._grind_beans()
        self._brew()
        print("Кофе готов!")


machine = CoffeeMachine()
machine.make_coffee()
```

Результат:

```text
Нагрев воды
Измельчение зёрен
Приготовление кофе
Кофе готов!
```

1. Основная программа вызывает только `make_coffee()`.
2. Метод сам запускает внутренние этапы в нужном порядке.
3. Методы с `_` предназначены для внутреннего использования по соглашению.
4. Пользователь класса не обязан самостоятельно вызывать каждый этап.

Если поменяется способ приготовления, достаточно изменить внутренние методы. Внешний вызов `machine.make_coffee()` может остаться прежним.

**Преимущество:** сложный процесс представлен простым действием. Здесь абстракция и инкапсуляция дополняют друг друга: абстракция задаёт удобную операцию, а инкапсуляция организует связанные внутренние методы и обозначает их назначение.

## 5.4. Пример 19. Расчёт заказа одной командой

В интернет-магазине покупателю важна итоговая стоимость, а отдельные этапы расчёта выполняет класс заказа.

```python
class Order:
    def __init__(self, price, quantity):
        self.price = price
        self.quantity = quantity

    def _get_subtotal(self):
        return self.price * self.quantity

    def _get_discount(self, subtotal):
        if subtotal >= 2000:
            return subtotal * 0.10
        return 0

    def get_total(self):
        subtotal = self._get_subtotal()
        discount = self._get_discount(subtotal)
        return subtotal - discount


order = Order(1000, 3)
print("К оплате:", order.get_total())
```

Результат:

```text
К оплате: 2700.0
```

Метод `get_total()` получает промежуточную стоимость 3000, вычисляет скидку 300 и возвращает 2700. Основной программе не нужно знать, какие функции вызываются внутри и в какой последовательности.

Использование `return` позволяет передавать промежуточные значения между методами. Если магазин изменит правило скидки, изменение можно выполнить внутри `_get_discount()`, не меняя вызов `get_total()`.

## 5.5. Абстракция и инкапсуляция: в чём отличие?

Абстракция отвечает на вопрос: **что нужно знать пользователю класса, чтобы им пользоваться?** Инкапсуляция отвечает на вопрос: **как организовать данные и связанные действия, чтобы объект контролировал своё состояние?**

Например, у банковского счёта метод `withdraw(amount)` представляет удобную операцию снятия денег — это абстракция. Проверка доступного баланса внутри метода и организация доступа к внутреннему атрибуту — инкапсуляция.

Типичные ошибки: пытаться представить в классе все возможные свойства реального объекта; выставлять наружу ненужные промежуточные операции; считать, что абстракция требует `abc` или обязательно использует `__`.

**Главная мысль:** абстракция помогает думать о назначении объекта, а не о всех подробностях его устройства.

# 6. Сравнение и совместное использование принципов ООП

## 6.1. Четыре принципа: разные задачи

| Принцип | Главный вопрос | Практическая польза | Пример |
|---|---|---|---|
| Инкапсуляция | Как управлять состоянием объекта? | Согласованность данных и проверка изменений | Изменение баланса через методы |
| Наследование | Как описать разновидность существующего класса? | Повторное использование и расширение поведения | `Warrior(Character)` |
| Полиморфизм | Как работать с разными объектами одинаково? | Общий код для разных реализаций | `character.attack()` |
| Абстракция | Какие свойства и действия важны для задачи? | Упрощение взаимодействия с объектом | `order.get_total()` |

Принципы не исключают друг друга. В одной программе можно использовать несколько из них одновременно. Не нужно, однако, специально применять все четыре к каждому классу: выбор определяется задачей.

## 6.2. Пример 20. Магазин с различными видами товаров

Создадим обычный товар и товар со скидкой. Цена должна оставаться неотрицательной, а общая программа должна получать стоимость любого товара одинаковым способом.

```python
class Product:
    def __init__(self, name, price):
        self.name = name
        self.__price = 0
        self.set_price(price)

    def set_price(self, price):
        if price < 0:
            return False
        self.__price = price
        return True

    def get_price(self):
        return self.__price


class DiscountProduct(Product):
    def get_price(self):
        return super().get_price() * 0.90


def calculate_total(products):
    total = 0
    for product in products:
        total = total + product.get_price()
    return total


book = Product("Книга", 500)
headphones = DiscountProduct("Наушники", 2000)

print(book.set_price(-100))
print(book.get_price())
print(headphones.get_price())
print("Итого:", calculate_total([book, headphones]))
```

Результат:

```text
False
500
1800.0
Итого: 2300.0
```

Как работает программа:

1. `Product` хранит цену во внутреннем атрибуте `__price`. Начальное значение 0 позволяет сохранить корректное состояние даже при некорректном отрицательном входном значении; в этом учебном варианте отрицательная начальная цена оставляет цену 0.
2. `set_price()` не принимает отрицательные значения. Попытка установить цену -100 возвращает `False`, исходная цена 500 сохраняется.
3. `DiscountProduct` наследует имя, хранение цены и метод её изменения.
4. Дочерний `get_price()` использует цену родителя и уменьшает её на 10%.
5. `calculate_total()` получает список и вызывает одинаковый метод у каждого объекта. Сумма равна 500 + 1800 = 2300.

Роль каждого принципа:

- **Инкапсуляция:** изменение `__price` выполняется через проверяющий метод `set_price()`.
- **Наследование:** `DiscountProduct` использует общую реализацию `Product`.
- **Полиморфизм:** функция подсчёта суммы вызывает `get_price()` у разных видов товаров.
- **Абстракция:** вызывающему коду достаточно знать, что `get_price()` возвращает цену к оплате, неважно, как она рассчитывается.

# 8. Полное решение проекта

Этот раздел предназначен для проверки самостоятельной работы. Сначала рекомендуется выполнить этапы 1–7 самостоятельно, а затем сравнить полученный код с решением.

## 8.1. Исходный код

```python
class Character:
    def __init__(self, name):
        self.name = name
        self.__health = 100

    def get_health(self):
        return self.__health

    def is_alive(self):
        return self.__health > 0

    def take_damage(self, amount):
        if amount <= 0:
            return
        self.__health = max(0, self.__health - amount)

    def heal(self, amount):
        if amount <= 0 or not self.is_alive():
            return
        self.__health = min(100, self.__health + amount)

    def get_damage(self):
        return 10

    def attack(self, target):
        if not self.is_alive() or not target.is_alive():
            return

        damage = self.get_damage()
        target.take_damage(damage)
        print(self.name, "атакует", target.name, "— урон:", damage)


class Warrior(Character):
    def get_damage(self):
        return 30


class Mage(Character):
    def get_damage(self):
        return 40


class Archer(Character):
    def __init__(self, name):
        super().__init__(name)
        self.arrows = 3

    def get_damage(self):
        if self.arrows > 0:
            self.arrows = self.arrows - 1
            return 35
        return 10


class Arena:
    def __init__(self, first, second):
        self.first = first
        self.second = second

    def play_round(self):
        if not self.first.is_alive() or not self.second.is_alive():
            return

        self.first.attack(self.second)

        if self.second.is_alive():
            self.second.attack(self.first)

    def show_status(self):
        print(self.first.name, "— здоровье:", self.first.get_health())
        print(self.second.name, "— здоровье:", self.second.get_health())

    def fight(self):
        round_number = 1

        while self.first.is_alive() and self.second.is_alive():
            print("Раунд", round_number)
            self.play_round()
            self.show_status()
            print()
            round_number = round_number + 1

        if self.first.is_alive():
            print("Победитель:", self.first.name)
        else:
            print("Победитель:", self.second.name)


# Основная часть программы
warrior = Warrior("Рыцарь")
mage = Mage("Мерлин")
arena = Arena(warrior, mage)
arena.fight()
```

Ожидаемый результат полностью совпадает с выводом этапа 6: маг побеждает в третьем раунде, здоровье воина равно 0, здоровье мага — 10.

## 8.2. Разбор решения

### Character — общие правила персонажа

Каждый объект хранит имя и собственное здоровье. Методы `take_damage()` и `heal()` следят за допустимыми границами здоровья. Метод `is_alive()` возвращает логическое значение, а `get_health()` — число.

Метод `attack(target)` сначала проверяет состояние обоих участников. Затем вызывает `self.get_damage()`. Для воина будет выполнен метод `Warrior`, для мага — `Mage`, для лучника — `Archer`. После этого метод передаёт полученное число другому объекту через `target.take_damage(damage)`.

### Warrior, Mage и Archer — разновидности персонажей

Воин и маг не дублируют методы здоровья. Они меняют только величину атаки. Лучник дополнительно хранит количество стрел и использует `super()` для инициализации общих атрибутов. После расходования стрел он наносит по 10 единиц урона.

### Arena — организация взаимодействия

Арена не рассчитывает, сколько урона наносит конкретный персонаж, и не изменяет его здоровье напрямую. Она вызывает общие методы и следит за порядком ходов.

Цикл `while` выполняется, пока оба персонажа живы. Переменная `round_number` — локальная переменная метода `fight()`. Она не нужна другим методам и поэтому не становится атрибутом объекта.

В третьем раунде первого поединка воин уменьшает здоровье мага с 40 до 10. Маг отвечает и уменьшает здоровье воина с 20 до 0. На следующей проверке цикл завершается. Маг объявляется победителем.

## 8.3. Где применены принципы ООП?

| Принцип | Реализация в проекте |
|---|---|
| Инкапсуляция | `__health`, методы `take_damage()` и `heal()` контролируют состояние |
| Наследование | `Warrior`, `Mage`, `Archer` используют общий класс `Character` |
| Полиморфизм | Один вызов `get_damage()` выполняет разные реализации |
| Абстракция | `attack()` и `fight()` представляют сложные действия простыми вызовами |

Кроме того, `Arena` взаимодействует с другими объектами, что позволяет независимо изменять правила арены и правила персонажей.

## Краткая шпаргалка

| Понятие | Запомнить |
|---|---|
| ООП | Объекты хранят данные и взаимодействуют через методы |
| Инкапсуляция | Объект управляет своим состоянием через предусмотренные операции |
| Наследование | `class Child(Parent):` — расширение и повторное использование поведения |
| `super()` | Использование реализации родительского класса при одиночном наследовании |
| Полиморфизм | Одинаковый способ вызова, различное подходящее поведение |
| Абстракция | Только существенные характеристики и понятные действия |

**Главный принцип проектирования:** не начинайте с желания использовать все четыре принципа. Сначала определите задачу, выделите сущности, распределите их ответственность и решите, какие данные и методы нужны каждой. Применяйте ООП там, где оно упрощает программу и делает её понятнее.

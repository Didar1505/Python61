# Практическая работа: Объектно-ориентированное программирование (ООП) в Python

## Цель работы

Закрепить навыки создания классов и объектов, научиться управлять состоянием объектов через методы, использовать наследование, полиморфизм и абстракцию, а также проектировать небольшие программы из взаимодействующих классов.

## Порядок выполнения

- Выполняйте задания последовательно. Каждое основное задание — отдельная программа Python 3.
- Создавайте объекты и проверяйте их работу вызовами методов. Недостаточно только объявить класс.
- Используйте параметры, локальные переменные и `return` для вычислений. Выводите возвращённые результаты через `print()` в проверочной части программы.
- Проверяйте не только обычные, но и граничные случаи, указанные в критериях.
- Не подменяйте вычисления заранее записанными ответами. Программа должна работать и с другими допустимыми аргументами.
- Формулировки сообщений можно изменять, если смысл и вычисленные значения сохраняются.
- Если не сказано иначе, входные данные имеют указанный тип; проверять ввод с клавиатуры не требуется. Для денежных расчётов используются целые рубли.
- В заданиях на инкапсуляцию изменяйте защищаемое состояние только через предусмотренные методы. Префикс `_` означает соглашение о внутреннем использовании, а `__` вызывает преобразование имени атрибута, но не обеспечивает абсолютной защиты.

print(taxi.calculate_cost(5))

- Проверьте все три вида транспорта для расстояния 5 км и автобус для 12 км.

**Пример работы расширенной программы:**

**Подсказка:** метод дочернего класса с тем же именем используется вместо метода родительского класса. Для автобуса параметр `distance` нужен для сохранения общего интерфейса.

Сервис рассчитывает цену, проверяет доступность транспорта и наличие средств, списывает оплату и оформляет аренду. При возврате транспорт снова становится доступным.

В проекте достаточно хранить данные в объектах во время работы программы. Не требуется ввод с клавиатуры, меню, база данных, реальное измерение времени или сохранение истории. ### Этап 6. Абстракция: оформление аренды одной командой

**Задание:**

- Добавьте в `RentalService` метод `rent_vehicle(customer, vehicle, hours)`, возвращающий строку со статусом операции.
- Метод проверяет условия в следующем порядке: транспорт входит в парк; количество часов — положительное целое число; транспорт свободен; баланс клиента достаточен для оплаты рассчитанной суммы.
- Если условие не выполняется, метод возвращает соответствующее сообщение и не меняет ни баланс, ни состояние транспорта.
- При успехе метод получает стоимость через `vehicle.calculate_cost(hours)`, списывает деньги методом `customer.pay(cost)`, оформляет аренду через `vehicle.rent(customer)` и возвращает сообщение об успешной аренде со стоимостью.
- Добавьте метод `return_vehicle(customer, vehicle)`, который проверяет наличие транспорта в парке, вызывает одноимённый метод объекта транспорта и возвращает понятное сообщение об успехе или отказе.

```text

Баланс: 550 руб.
Транспорт уже занят
Недостаточно средств
Некорректное количество часов
Баланс: 550 руб.
Транспорт возвращён
Самокат свободен: True
```

**Подсказка:** проверки должны предшествовать списанию денег. В этой последовательной учебной программе после успешных проверок `pay()` и `rent()` завершатся успешно. Внешний код обращается к сервису, не управляя каждой операцией отдельно. При возврате предоплата не возвращается.

**Проверка (5 баллов):** проверки принадлежности к парку и часов (1), проверка доступности и средств (1), успешное оформление через методы объектов (1), отсутствие изменения состояния при любом отказе (1), корректное возвращение транспорта только его арендатором (1).

### Где в проекте применяются принципы ООП?

| Принцип | Что необходимо продемонстрировать |
|---|---|
| Инкапсуляция | Баланс клиента изменяется через `deposit()` и `pay()`, занятость транспорта — через методы аренды и возврата |

| Полиморфизм | Сервис обращается к `calculate_cost()` независимо от конкретного вида транспорта |
| Абстракция | Клиентский код вызывает `rent_vehicle()` и `return_vehicle()`, не повторяя внутренние проверки и расчёты |
